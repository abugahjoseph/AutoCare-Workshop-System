# Sprint Plans

## Sprint 1 — Discovery and foundation (Weeks 1–3)
**Goal:** agree the problem, requirements and architecture.
- Interview 2–3 potential workshop users or use lecturer-approved assumptions.
- Finalise scope, personas, SRS and acceptance criteria.
- Create GitHub repository, issues, branching and README.
- Build Flask skeleton and SQLite models.
**Definition of done:** SRS reviewed; repository works locally; initial schema created.

## Sprint 2 — Core workflows (Weeks 4–6)
**Goal:** implement customer, vehicle and job-card workflows.
- Customer and vehicle registration.
- Create job cards and calculate estimated total.
- Dashboard and status workflow.
- Add automated tests and review code.
**Definition of done:** core workflows pass team acceptance tests; test evidence saved.

## Sprint 3 — Integration and delivery (Weeks 7–9)
**Goal:** finish notifications, payments and submission evidence.
- Add SMS adapter and mock/Twilio configuration.
- Add payment records.
- Complete test plan, risk review and UML/design documentation.
- Rehearse 10-minute demonstration and presentation.
**Definition of done:** clean setup from README; tests executed; demo rehearsed; individual reflections completed.

## Weekly ceremonies
- 15-minute planning/check-in.
- Mid-sprint progress review.
- Sprint review/demo and retrospective.
- Rotate roles every three weeks; capture decisions in GitHub issues or meeting notes.
