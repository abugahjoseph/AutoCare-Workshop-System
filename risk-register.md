# Risk Register

| ID | Risk | Likelihood | Impact | Mitigation | Owner |
|---|---|---|---|---|---|
| R1 | Team member unavailable | Medium | High | Shared documentation, pair work, weekly handover | Project Manager |
| R2 | Scope expands beyond schedule | High | Medium | Freeze core features; backlog enhancements | Project Manager |
| R3 | Database corruption/loss | Low | High | Back up SQLite file before demos; use sample data | Lead Developer |
| R4 | SMS credentials fail or incur cost | Medium | Medium | Default mock mode; use Twilio test/trial credentials | Lead Developer |
| R5 | Incorrect or duplicate vehicle data | Medium | Medium | Required fields and unique registration constraint | Tester |
| R6 | GitHub contributions not visible | Medium | High | Each member commits/pushes work using own account | All |
| R7 | Exposure of customer data | Medium | High | Use fictional demo data; restrict access; no secrets in repo | All |
| R8 | Demo machine/network failure | Medium | Medium | Test offline/mock mode; prepare screenshots and local backup | Team |

Review risks at each sprint review and update likelihood, impact, owner and mitigation.
